# Windows component-library preview — October 25, 2026

This release delivers the current reusable C# / WinUI 3 component library,
its registered catalog fixtures, regression sources and both fictional
Monitoring and Editorial component demos. It is a development preview.
It does not claim final acceptance of the 112-entry inventory.

Download the assets from the
[GitHub release](https://github.com/gaulatti/orchard/releases/tag/v0.1.0-preview.20261025).

## Use the catalog

Download `Gaulatti.Orchard.Catalog.0.1.0-menubar-peer-metadata-v1-local-win-x64.zip`,
extract the complete archive to a writable folder on Windows x64, and run
`Orchard.Catalog.exe` from that folder. Keep the accompanying DLLs, fonts and
assets together. The Monitoring and Editorial fixtures use fictional local data.

## Use the library

Download `Gaulatti.Orchard.0.1.0-menubar-peer-metadata-v1-local.nupkg` and place it
in a local NuGet feed. Add that feed to your consumer's NuGet configuration,
keeping nuget.org available for the package's existing dependencies. Reference
the exact version:

```xml
<PackageReference Include="Gaulatti.Orchard"
                  Version="0.1.0-menubar-peer-metadata-v1-local" />
```

Follow the [package setup instructions](../package-readme.md) for the WinUI
resource dictionaries, fonts and native dependencies. The package is supplied as
a release asset; this release does not publish it to nuget.org. Its existing
`-local` version suffix is retained to distribute the exact verified bytes.
The source checkout pins the .NET SDK in `global.json`.

## Verified delivery boundaries

The selected library SHA-256 is
`c0597e9f4cb9499cc09aafb59da2b321f6e302c7fe11eecf5d08a357a9110483`.
The binaries were built before the delivery commit. Their frozen source-input
manifest identifies the tested bytes; the delivery commit includes those
component sources and subsequent delivery documentation.

- Source and independent NuGet-consumer builds passed for x64 and ARM64.
  ARM64 compilation is not ARM64 runtime verification.
- Source, independent NuGet and runnable catalog hosts each passed 30 Menubar
  states, 28 contracts, 40 radio-provider operations, 164 keyboard-controller
  cases, eight peer-tree observations and 12 group/lifecycle cases.
- Those hosts verify 12 Menu peers and 18 radio selection-container associations.
  Their audit suites rejected 94, 93 and 94 negative cases respectively.
- Both demos passed 66 checks and 577 isolation guards against this library;
  their audit rejected 25 negative cases.
- All 550 catalog archive entry streams were checked against the frozen files.
- The delivery's portable regression suite passed all 496 tests, with no failures

These checks repair duplicate menu labels, expose menus through their triggers,
retain original radio-group selection containers, and preserve caller-controlled
state. They do not establish external automation-client event delivery or
physical keyboard/pointer routing. Unchanged components retain their existing
scoped evidence; this release does not claim that every historical test was rerun.

The accompanying `verification.json`, source-input manifest and audit reports
record these results. `SHA256SUMS.txt` covers the release assets.

## Remaining acceptance work

The inventory has 112 entries started/in progress, zero pending and zero accepted;
both required demos remain in progress. This is not a completion percentage.
Remaining requirements include native ARM64 runtime, applicable display/text
scaling, visual and real-time motion review, external automation-client delivery,
and actual keyboard, pointer and focus behavior.

DataTable's earlier measured library baseline retains 24 failing timing medians
out of 120 profiles. At 16,384 rows and page size 100, next-page median latency
was 1,715.0988 ms against a 1,000 ms budget. This preview has not been performance
measured; it does not claim to fix that failure.

The library-only scope and both demos remain in force. Narrator and Windows/OS
contrast campaigns are excluded. Hosted Actions are intentionally suppressed for
this delivery at the user's request; local build/runtime results are reported
separately from CI.
