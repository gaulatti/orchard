# Context Menu

`BleeckerContextMenu` is a native `MenuFlyout` for a target's `ContextFlyout`.
It uses the pinned Context Menu recipe: 160-DIP minimum width, 36-DIP minimum
item height, Encode Sans Regular 13/19.5 text, 10/6 item padding, five-DIP item
corners, and a 32-DIP inset option. Light and Dark colors come from Orchard's
theme resources. The styles and tokens are generated by the repository's
existing generators.

Assign original `MenuFlyoutItem` or `BleeckerMenuContentItem` instances to its
`Items`. The component retains caller `Click` handlers, commands, command
parameters, content, enabled bindings, presenter-style overrides, and native
`Closing` cancellation. The catalog shows ordinary, disabled, inset, and
composed-content items in both themes.

`IsModal` defaults to `true`. Bind it to `false` when the first click on an
outside control should remain available while the menu is open. WinUI's
`OverlayInputPassThroughElement` handles this native outside-input path; live
option changes retain the open menu and original items. A target inside an
active `BleeckerModalHost` uses the same native presenter. Its popup belongs to
the active owner: an upper modal collapses the popup, shielding its pointer,
keyboard and automation surface without rewriting caller enabled state. When
the upper modal closes, the same presenter and caller items return. A native
popup scope permits focus on its original items only while their owner is
active. Escape closes the menu before the parent modal processes that key.
Closing or removing the owner retires the native popup even if the caller
canceled a normal close.

The earlier shared-plane portal was an internal prototype. It retained native
items in hidden probes but intercepted physical owned-item clicks. It is no
longer the public Context Menu implementation. Historical source captures and
prototype evidence remain available; they do not establish current behavior.

Current x64 catalog checks exercise four physical paths on one library build:
owned and unowned menus, each in modal and nonmodal mode. Shift+F10 opens and
Escape dismisses each menu; right-click opens it and a left-click invokes the
original item. Both nonmodal paths deliver the first outside click to the
caller control. A separate owned keyboard check confirms that the first item
receives focus and Enter invokes its caller action. Hidden Light/Dark checks
cover 38 option/lifecycle cases and 12 owned-menu cases, including upper-owner
shielding, live content/theme/binding/style changes, canceled dismissal,
owner teardown, and remount. Root layout and actual catalog action checks also
pass. The candidate `0.1.0-preview.20261029.3` NuGet package compiled in the
x64 package consumer with zero warnings, and the restored package hash matched
the candidate. A physical owned-modal item click on the same DLL invoked the
original catalog handler. The 150% no-clipping and reduced-motion checks remain
unverified, so this component is not yet accepted under the current milestone.
Open/close animation remains disabled. ARM64 runtime is build-only and
unverified for this milestone.
